## 1. Summary

Open Local Dictation is a tray app that types what you say into whatever application has keyboard focus.
It was split out of Open Local Assistant's dictation feature and keeps that feature's behaviour, but has no
chat, no LLM, no text-to-speech, no correction profiles and no database.

## 2. User-facing behaviour

### 2.1 First run
No model is installed, so the Settings window opens by itself on the **Speech model** tab. The user either
downloads a Whisper model (tiny, base, small or large-v3 turbo; one at a time, with progress, cancel, and SHA-256 verification) or
points the app at a folder that already holds models (§2.6). Until a model exists, pressing the hotkey shows
an overlay error: "No speech model is ready. Open Settings and download a Whisper model."

### 2.2 Dictating
* Default hotkey `Ctrl+Alt+Space`, **hold to talk** (alternatively press to start / press to stop). Modifier-only combinations need at least two modifiers (a single Alt would fire on every Alt press).
* On press the app remembers the focused window, shows the overlay (never taking focus) and starts listening. The header shows the state, a live 24-band spectrum and the language pill; a tab above the card reads "Insert into: <app>" and follows focus changes to other applications while dictating.
* Speech is split into utterances by a voice-activity detector; each finished utterance is transcribed and appended, so text grows while the user still talks. A cold model load takes seconds; the meter keeps moving and audio heard meanwhile is kept and processed first.
* `Esc` cancels from anywhere (polled, never swallowed). The overlay's X, **Start over** and **Insert/Review** buttons do the same from the mouse. A take also ends after `autoStopSilenceSecs` of silence (default 8 s) or 5 minutes.

### 2.3 Review before insert (default on)
After the take, the overlay turns into an editable text area ("Review — edit if needed"), becomes focusable, and global review keys are registered so they work even though the destination app owns focus:
`Ctrl+Enter` insert · `Ctrl+Shift+Enter` retry · `Ctrl+Shift+Backspace` cancel (and `Esc`). **Copy** puts the text on the clipboard. On insert the overlay shrinks back, focus is returned to the remembered window (`AttachThreadInput` + `SetForegroundWindow`), 150 ms later the text is inserted.
With review off, words are typed live as they are committed; "Insert" at the end reconciles the screen to the final text.

### 2.4 How text is inserted
* **Typing** (default): real key events by scancode using the destination window's keyboard layout, 16 ms per character. This is byte-exact in Notepad and Chromium; the Unicode `SendInput` path drops and duplicates characters in classic edit controls and is used only for characters the layout cannot produce (emoji, or Arabic under an English layout).
* **Pasting**: the clipboard is set, Ctrl+V is sent, the previous clipboard text is restored 300 ms later.
* Live typing is **word-committed**: only whole words reach the screen (`committed_prefix`), so a word still being revised never needs backspacing. If an injection fails the typer marks itself desynced and the next apply erases what was confirmed and retypes.
* Before any one-shot insert the app waits (max 3 s) for the hotkey's modifier keys to be released, so Ctrl/Alt do not turn typed characters into shortcuts.
* "Add a space after the text" appends one space to the final text.

### 2.5 Language
The overlay's language pill (and Settings → Dictation → Language) selects Automatic or one of ~80 Whisper languages with a filter box. The choice is saved. Mid-take, changing it restarts the take. Whisper switches language on a loaded model in place (`stt::engine::set_language`, well under a millisecond) instead of reloading. Settings → Dictation → "Languages in the overlay menu" switches the overlay menu between All and a chosen set (dialog with checkboxes, checked languages grouped on top with a divider above the rest; `shownLanguages`, empty = all). The current language and Automatic are always listed, and Settings → Language lists the same chosen set.

### 2.6 Models folder
`modelsDir` points at a folder shared with other apps; nothing is moved or copied.
* Catalog models are found in `<dir>/stt/<id>` or `<dir>/<id>` (so choosing the `stt` folder itself works) when `.complete` exists **or** the folder holds valid Whisper files.
* Any other folder directly in `<dir>` or `<dir>/stt` with `encoder*.onnx`, `decoder*.onnx`, `*tokens.txt` and no file containing `joiner` is listed as **Existing** (e.g. `whisper-turbo`).
* Downloads go to `<dir>/stt/<id>` (or `<dir>/<id>` when `<dir>` is named `stt`).
* **Use default folder** asks for confirmation. Changing the folder is refused during a download or recording, unloads the recognizer and resets `model` to automatic.
* The app **never deletes models** (no command, no button).

### 2.7 Processing (CPU / GPU)
* Segmented control CPU / GPU (NVIDIA). GPU is disabled when DXGI finds no NVIDIA adapter.
* Choosing GPU without the CUDA libraries shows a notice: **Use existing** (link Open Local Assistant's pack, instant) or **Download** (≈ 1.7 GB, progress, cancel).
* A device change shows "takes effect after a restart" with **Restart now**.
* The app never removes the CUDA libraries.
* Crash guard: if a GPU start dies before a model loads, the next launch switches `device` to `cpu`.

### 2.8 Settings window
Frameless, 920 x 660, resizable down to 820 x 560 and maximizable; own title bar (app icon, minimize, maximize / restore, close-to-tray; double-clicking the bar also maximizes). The maximize button follows `settings://maximized`, sent by the window's `Resized` event. The title bar and the sidebar's brand mark show the real app icon (`public/app-icon.png`, a copy of `src-tauri/icons/128x128.png`; replace it whenever the app icon changes). A left **sidebar** (`Sidebar`) replaces the old tabs: **Home** (status cards for model, shortcut, language and microphone; the microphone card has a Test microphone level meter fed by `mic_test_start` / `mic://level`, opened only while it runs and stopped on leaving the page, on blur or when the window hides; with no model installed a call to action downloads the recommended one), **Models** (the Speech model list and the Processing card), **Languages** (dictation language, the overlay-menu language list, model per language), **Dictation** (shortcut, behaviour, microphone, review, insert method, trailing space), **Overlay** (Appearance, Always available and Position cards; one Reset position for the overlay and the taskbar button) and **App**. The sidebar has a search box (`INDEX` in `Settings.tsx`; picking a result opens the page and flashes the row), arrow-key navigation, Ctrl+1..6, an amber dot on a section that needs attention (no model, restart pending, shortcut not registered), and the shortcut and version at its foot; below 880 px wide it folds to icons. The last open page is kept for the session. A Saved chip appears after each saved change. Each page scrolls inside the content column. Model rows show an In use badge, a Use button, Load / Unload (immediate, no dialog) or Download, and a row menu (Load when the app starts, Hide from the list); the folder and Your own model sit in a collapsible section that opens by itself when no model is installed. Rows keep a one-line hint; longer text is in an info tooltip. Every Reset button has an icon and asks first through the themed `Dialog`. Settings text is one step larger than the overlay's (`.settings-shell` overrides `--text-xs` / `--text-sm`).

### 2.9 Tray
Left click opens the idle dictation window. Menu: Show dictation window (opens the idle overlay; nothing is recorded until the shortcut or the mic button), Hide dictation window, Settings, Quit. There is no title entry: Windows highlights even a disabled item on hover, and the tooltip already names the app. Both go through `window::open_overlay_from_tray`: while the taskbar button is on, the idle page shows its pill only while the button is pointed at, so the tray also sends `overlay://tray-open` (`true`) and the pill stays open above the button without a hover. It closes when another window comes to the front (an `EVENT_SYSTEM_FOREGROUND` WinEvent hook on the main thread, `window::tray_pill`; the taskbar, the tray, menus, hidden windows and the overlay itself do not count, nor anything in the first 400 ms while the tray menu closes; then `overlay://tray-open` `false`), with its X, or with the tray's Hide entry (the window hides and the hook is removed). A second launch opens settings.

## 3. Technical details

### 3.1 Speech pipeline (`stt/`)
1. `VoiceSessions::start` validates a model exists, stops any earlier session (joining its thread), opens the microphone (`Capture::start`: cpal, mono downmix, resample to 16 kHz, 100 Hz high-pass, retry up to 4 times if the driver kills the stream within 250 ms) and spawns the session thread.
2. `warm_up` loads the recognizer on a scoped helper thread while the session thread forwards levels and buffers samples.
3. `run`: samples feed a Silero VAD (CPU, window 512, `vadThreshold`, min silence `silenceMs`, min speech 250 ms, max 20 s). Each finished segment (>= 350 ms) is sent to a worker thread that runs `Recognizer::transcribe` and `clean_transcript`; results become `partial` events. Audio not covered by a segment stays in `buffer` and is transcribed once more at the end.
4. On stop the remaining queue and buffer are transcribed; one `transcript` event carries the final text. With `discard` (cancel/retry) nothing is emitted.
5. `clean_transcript` removes bracketed captions (`[BLANK_AUDIO]`, `(applause)`, `<|nospeech|>`), music notes, and known silence hallucinations ("Thank you.", "Untertitel der Amara.org-Community", …).

### 3.2 Overlay window
480 x 176 card inside a window with 300 px of invisible room above and below (for the language menu). `SetWindowRgn` clips the window to the card, the destination-app tab and the open menu, so the transparent room neither shows nor blocks clicks. Frame styles are stripped before every region change (Windows otherwise draws a classic border), and a window subclass (`keep_frame_styles_off` / `no_frame_proc`, installed on the main thread when the overlay is created) vetoes them in `WM_STYLECHANGING`, so the window library can never put the caption, thick frame or edge styles back and the classic title bar cannot be drawn in any order of window calls. The overlay is built with `no_redirection_bitmap` (`WS_EX_NOREDIRECTIONBITMAP`): it has no GDI surface, only the WebView2 content, because that surface was presented white for a frame each time the region opened after a show (a white pill flashing behind the taskbar hover pill's pop-in). When a hidden window is shown, the region is first set to empty (`clip_overlay_to_nothing`) so nothing of a stale layout is painted. Showing an overlay that is already on screen (the pointer back on the taskbar button, a pin or layout change) keeps its current shapes and only reapplies the region; emptying them blanked the hover pill for a frame. Listening uses `WS_EX_NOACTIVATE`; review clears it. All transitions run on the main thread (`on_main`). Dragging uses manual `setPosition` with Shift = horizontal-only and Alt = vertical-only; the card position is saved (`overlayX/Y`) except for programmatic moves (`suppress_persistence`).

### 3.3 Target application
`remember_target` stores the foreground HWND at start (ignoring this app's own windows). `watch_dictation_target` polls every 100 ms while a take is active and republishes `dictation://target` when focus moves to another external window. The friendly name comes from the process image name (`application_display_name` maps Code, Notepad, Word, Excel, PowerPoint, Chrome, Edge, Firefox, else the exe stem).

### 3.4 Downloads
`ModelStore::install` streams each file to `.staging-<id>`, hashing as it goes (progress every 250 ms), compares SHA-256 after each file, and only then renames the folder into place and writes `.complete`. Cancel, error or mismatch removes the staging folder.

### 3.5 Errors
Rust errors serialize as `{code, detail}`. The UI shows the mapped fix text; `detail` sits under "Technical details" in `ErrorNotice`.

### 3.6 Logging and privacy
Daily rolling log in the Tauri log dir, filter via `LOCAL_DICTATION_LOG` (default `info`). Dictated text and audio are never logged.

## 4. Business rules
* One take at a time (`dictation_busy`, session numbers); a new take cannot start during review or transcription. The shortcut handler logs each press and release (flags only: active, busy, transcribing), and a start dropped because a take is still being inserted, so a missed hotkey can be traced in the log file. In hold mode a tap (held under 400 ms, `TAP_MAX` in `shortcuts.rs`) latches recording on; the next press stops it. A longer hold stops on release. When the overlay window is shown from hidden, Rust emits `overlay://shown` and the page reveals the card with a 240 ms zoom-in from 0.55 (`overlay-pop` in `app.css`, emphasised-decelerate `cubic-bezier(0.2, 0, 0, 1)`) on the bubble circle or the small pill. Before hiding it emits `overlay://hidden`: the page resets to a bare idle card and is invisible (`away`) until the next show, so no stale pill or result flashes. A tray click on an already visible overlay does not replay it. Without opening the pill the bubble closes with a middle click on the circle (idle: unpin and close, like the X; during a take: cancel) or with the tray entry "Hide dictation window". In the bubble style the pill and the mic circle are one rigid body: the circle is centred in the window and the pill fills it, neither moves inside it, and only the window is ever dragged (`useOverlayDrag`). The pill's header drags on a plain press. The circle drags only while Ctrl is held: a press on the circle or on the mic button without Ctrl is always a click (it starts or stops dictation, however far the pointer travels), so a stray press near the mic can never shove the overlay across the screen. With Ctrl the whole 42 px circle is the handle and the drag starts on the press itself, with no slop and no click, so the button's face can be grabbed and not only the 5 px ring around it. Holding Ctrl over the circle also keeps the hover pill shut, so it is not in the way, and shows the `grab` cursor on the circle and the mic button alike. The modifier is read off the pointer events, not a key listener, because the overlay never takes focus; releasing Ctrl while still hovering brings the pill back. While any drag is live the whole page shows `grabbing` (`html.dragging` in `app.css`, set by `setGrabbing` and cleared on release, on `pointercancel` and when the window loses focus, so it can never stay stuck). The circle at rest shows the default cursor and the header `move`. A drag never goes over the taskbar, in any style: the drawn part has to stay inside the work area of the monitor under it (the monitor without the taskbar and docks, `Monitor.workArea`). Only the drawn part is bounded, not the window, which is MENU_ROOM (300 px) taller above and below the card to leave the language menu room; the card box's lower edge is the limit in every style, which is also what `card_on_screen` in window.rs uses when a saved position is clamped on show, so the two agree. Sideways the whole window stays inside, so the circle never comes nearer a screen edge than half the pill; in the bubble style the pill pokes out above the card box and is kept below the work area's top as well, and the circle sits a few px above the taskbar so it floats. Because nothing moves inside the window, the clip region's shapes change only when the window is resized, never during a drag. Closing (X, Esc, unpin) first emits `overlay://hiding` (180 ms zoom-out to 0.55, `overlay-close` in `app.css`); Rust hides the window 210 ms later (`CLOSE_ANIM_MS`, a frame past the animation so the window never hides mid-fade; `HIDE_TOKEN` cancels it when the overlay is shown again). On first start the page keeps the card invisible until the settings have loaded (2 s fallback) and then plays the pop-in, because `overlay://shown` can arrive before the page is ready.
* Cancel always wins over a pending transcript (`dictation_cancel` consumed by `run_dictation`).
* Review and live typing are mutually exclusive: with review on, `partial` events type nothing.
* A transcript with no text never shows an edit window: `dictation_insert_now` skips the live preview when nothing was heard, and `run_dictation` closes a preview (and returns focus) when the final text turns out empty, then shows `empty`.
* A late `idle` of an old session never ends a newer one in the UI (session numbering, overlay ignores `idle` while previewing/reviewing).
* The overlay never hides while a take is active or busy (`overlay_hide_is_current_and_idle`).

## 6. Relationship to Open Local Assistant
Independent repository, data folder (`%APPDATA%\com.localdictation.app`) and identifier (`com.localdictation.app`). The only contact: the CUDA pack of Open Local Assistant (`%APPDATA%\com.localassistant.app\gpu\cuda-1.13.8`) is linked when present, and models may live in a folder both apps point at.


### Pinned and small overlay

`overlayPinned` keeps the overlay window shown and always on top. `hide_overlay_window` (window.rs) then docks it as an idle card instead of hiding it and emits `overlay://idle`, which the page uses to reset itself. Nothing is recorded while idle: only the global shortcut, the tray entry or the overlay's mic button (`dictation_toggle`) start `voice.start()`. `overlayMini` switches the window to a 400 x 68 pill (mic, short level meter, destination app name, expand, pin, cancel, in that order; a subtitle bubble above the pill shows the live text, only while there is some, and is added to the window region through `dictation_overlay_menu`; no destination-app tab, no language menu). In review the same bubble becomes the editor (textarea, a hint row with the review keys, a Copy | Retry | Cancel button group, Insert), so the pill never grows; `set_overlay_review` keeps the bubble's region rectangle in the small layout. While listening the mic button becomes a stop (insert) button and the full card has a Cancel button (the header X cancels too). The Overlay tab of Settings has the pin, small, lock-size and position options; the overlay header has pin and size buttons. `overlayHorizontalOnly` (on by default) limits dragging to the x axis: the page zeroes the vertical movement and `show_overlay_now` puts the card back on the bottom edge of its monitor's work area (`docked_y`), whatever y was saved. `overlayPositionLocked` disables dragging (and the double-click reset). A gear button in the header (both layouts) opens Settings through `settings_open`; `overlayShowSettings` (Settings > Overlay) hides it. `overlayOpacity` (30-100 %, Settings > Overlay) sets the CSS variable `--ov-a`, which mixes the overlay card and subtitle bubble backgrounds with transparent; text and buttons stay solid. `overlayLayouts` ("small" by default, "large" or "both") limits which sizes exist: the size button only appears with "both", and `Settings::effective_mini` decides the layout (small -> always mini, large -> never, both -> `overlayMini`).

### Shortcut while busy

Pressing the dictation shortcut while the last take is still transcribing (`VoiceSessions::is_transcribing`) drops that take (`cancel_transcription`: its `Transcript` is never emitted) and starts a new recording; while a result waits for review it discards the review and starts again. The new recording begins once the running transcription pass ends (it cannot be interrupted).

### Resizable small overlay and tooltips

The small pill has a drag handle on its right edge (width only, 320-800 px, double-click resets to 400). `overlay_resize` resizes the window live and saves the width on release; `overlaySizeLocked` (Settings, Overlay tab) removes the handle. Tooltips are themed: `src/components/Tooltip.tsx` (`TooltipLayer`, mounted once per window in `main.tsx`) replaces the native `title` tooltip by moving the text to `data-tip` while hovered and drawing a `.tooltip` using the theme tokens. In the overlay window no bubble is drawn (the card sits on the taskbar and the window is clipped to it): `TooltipLayer inline` hands the text to the overlay, which shows it in its header in place of the status label while the pointer is on a button.

### Settings icons and duplicate-text fix

Tabs, card headings, setting rows (`Row icon`), segmented options and Cancel/Save/Edit/Dismiss buttons carry lucide icons (`Card icon`, `Segmented option icon`). In `stt/session.rs` the audio of a finished utterance is now cut from the tail buffer by its stream position (`SpeechSegment::start` + length, tracked against `buffer_base`), not by a length guess: with a long pause before speaking, part of the utterance used to stay in the buffer and was transcribed a second time when recording stopped, so the text appeared twice.

### Microphone check

`mic.rs` answers "is there a microphone to dictate into?": the chosen input (`microphone`, else the system default, as recording falls back) must be an active capture endpoint and not muted (`IMMDeviceEnumerator`, `IAudioEndpointVolume::GetMute`), and none of Windows' microphone privacy switches (all apps, desktop apps; machine and user, under `CapabilityAccessManagerConsentStoremicrophone`) may say `Deny`. The result is `ok`, `muted`, `missing` (unplugged, disabled, none) or `blocked`. A 2 s watcher thread (`lib::start_mic_watch`) logs changes, emits `mic://status`, turns the tray icon red (`tray::set_mic_status`: the icon's teal tinted to red, tooltip with the problem and the fix) and the idle taskbar button red with a slashed mic. Starting a dictation (`shortcuts::start_dictation`) checks again live: without a usable microphone nothing starts and the overlay shows the warning for a moment (errors `mic_missing`, `mic_muted`, `mic_blocked`, texts in `strings.ts`).

The small overlay's width (dragged on its right edge, or grown to fit its header) changes around the window's horizontal center (`window::resize_overlay_mini`; the edge follows the pointer at twice its travel), so the bubble's circle, which is centered in the window, and the taskbar button the pill is anchored to stay under the pill's middle. Anchored, the window is re-placed with `anchored_geometry` (clamped to the work area); otherwise it stays on its monitor when it fits.

### Color profiles

`colorProfile` (Settings > App > Accent colour, a row of glossy swatches; default `teal`) picks the accent of the app from the five in `profile::PROFILES`: teal, blue, green, amber and slate (grey), kept few so each one is plainly different from the others. There is no red or pink one on purpose (a unit test rejects any accent or icon tint in the red hues): red is the microphone alert and the listening disc, and an accent must never be mistaken for it. A stored `rose` (an earlier build) falls back to teal. A stored id that is no longer in the table falls back to teal. The table is the one source: a profile is one row (label, accent and ink for light and dark backgrounds, icon tint) and a unit test checks contrast of every ink on its accent. The pages fetch it with `color_profiles` (`profiles.ts`: `loadProfiles` writes `--p-light`, `--p-ink-light`, `--p-dark`, `--p-ink-dark` per `data-profile` into a style sheet; `tokens.css` derives `--accent` and its siblings from them with `color-mix`, teal being the hand-written default). It is applied in four places: the pages (`applyProfile` sets `data-profile`; the overlay pill and the Settings window follow), the window's app icon (the title bar and the sidebar brand mark: `useAppIcon` recolors `/app-icon.png` on a canvas with the same math as Rust, cached per tint), the tray icon (`tray::refresh_icon` with `profile::tint_icon`: hue turned, saturation and lightness scaled, white bars kept; green keeps the original icon, which is green already; every other profile turns its hue) and the taskbar button (`taskbar::set_profile` -> `draw::palette`). Red, the "no usable microphone" color, belongs to no profile: the tray icon (`tint_red`, wins over the profile in `refresh_icon`) and the button stay red, the listening disc stays red, the success and fail colors are unchanged. `lib::apply_color_profile` runs at start and on every `settings://changed`. High contrast mode keeps its own accent. The Theme setting (system / light / dark) is separate.

### Taskbar button

Optional (`taskbarWidget`, off by default, Settings > Overlay; bottom taskbar only). `taskbar.rs` runs a dedicated thread with its own message loop: a hidden control window (it receives the broadcasts a child window never sees: `TaskbarCreated`, `WM_SETTINGCHANGE`, `WM_DISPLAYCHANGE`, `WM_DPICHANGED`) and the button, a `WS_CHILD | WS_EX_LAYERED` window created directly under `Shell_TrayWnd`. A child of another process's window shares its input queue, so the thread only draws and forwards input; the app talks to it by `PostMessageW` and callbacks that return at once. Layered children need the `supportedOS` manifest entry (see developer_guide).

- Placement: the button's position (`taskbarWidgetX`, logical px from the taskbar's left edge) is fixed: tray icons coming and going, other widgets resizing or the taskbar's contents changing never move it; only the user does, by dragging it (saved on release). Only the first time (no saved position, or after "Reset position") the default spot is worked out: just left of `TrayNotifyWnd`, stepping left past any other widget there (windows at any depth in the taskbar band narrower than half of it, outside the taskbar's own parts, e.g. TrafficMonitor); that spot is then saved as the position. A saved position is only clamped into the taskbar's width. Re-checked every 0.5 s and on display, DPI and settings changes (it follows the taskbar's size and DPI, and is raised if the taskbar covered it). A taskbar that is not at the bottom, or whose parts are not found, gives a reason shown in Settings (`taskbar://status`). Explorer restarts are survived (`TaskbarCreated`, then a retry every 5 s while there is no taskbar).
- Shape: the window is an 82 x 32 logical px capsule (`draw::BOX` 32 for the disc, `draw::CHIP_W` 50 for the indicator) holding the mic disc on the left and a language indicator on the right (`AUTO`, or the code in capitals, at most 4 letters: `taskbar::language_label`). The capsule is a faint tint of the taskbar's ink that brightens on hover. The text is drawn by GDI (`imp::text_mask`: Segoe UI semibold, grayscale smoothing, white on a black DIB) and its brightness is used as coverage by the software renderer; the mask is cached per label and DPI. `lib.rs` listens to `settings://changed` and calls `taskbar::set_language` (a `WM_APP + 5` post), so any change of the language (overlay menu, Settings, this button) updates it.
- Drawing: software-rendered premultiplied BGRA (`taskbar::draw`, signed-distance shapes with soft edges) pushed with `UpdateLayeredWindow`: teal disc; red stop square with a pulsing ring while listening; spinner while transcribing; pencil in review; green check (`LINGER_OK_MS`) after inserting; grey cross (`LINGER_MSG_MS`) for empty, cancelled or error. Colors follow the app's tokens, light or dark by the taskbar theme (`SystemUsesLightTheme`). The 16 ms animation timer only runs while listening or transcribing. `lib::emit_state` is the single place `dictation://state` is sent and also feeds `taskbar::set_state` (idle is held back 200 ms because the voice session reports it just before the dictation that follows).
- Input: click toggles dictation (a result waiting for review gets its editor focused instead; a take being transcribed is ignored); resting 300 ms opens the pill; dragging it moves the button and saves the offset, but only when Ctrl was held at the press (`MK_CONTROL` in `WM_LBUTTONDOWN`; then a press that moves more than 4 px is a drag, a shorter one a click). Without Ctrl a press is always a click, so the button cannot be moved by accident. The pointer becomes a grabbing hand: an open hand while Ctrl is held over the button, a closed fist from the press until release (`WM_SETCURSOR`). These are the browser's own `hand_grab.cur` and `hand_grabbing.cur` (Chromium, BSD; `src-tauri/assets/`, embedded with `include_bytes!`), the same as the pill's CSS `cursor: grab` / `grabbing`; `cursor_from_cur` reads the largest image and the hotspot of each file and builds the cursor with `CreateIconFromResourceEx`. The four-arrow move cursor is the fallback if that fails. Only the mic disc opens the pill on hover: resting on the language indicator does nothing (`Local.on_chip`; moving from the disc onto the indicator ends the hover). Right click anywhere on the button (`WM_RBUTTONUP`) opens a native popup menu of languages just above the taskbar at the pointer (`taskbar::imp::language_menu`: `TrackPopupMenu` with `TPM_BOTTOMALIGN | TPM_CENTERALIGN | TPM_RETURNCMD | TPM_RIGHTBUTTON`, run on the widget's own thread and owned by the widget window; only one menu at a time). Before it opens, the taskbar's top-level window (`GetAncestor(GA_ROOT)`) is brought to the front, because a menu closes on a click elsewhere only while the window above its owner is in front; and while it is open an `EVENT_SYSTEM_FOREGROUND` WinEvent hook (out of context, so it runs through the menu's modal loop) calls `EndMenu` when any window other than the taskbar or the menu comes to the front. A right click on the button while the menu is open closes it on the press, and the release that follows (within `TOGGLE_MS`, 1.5 s) does not open it again: a second right click toggles the menu shut. (Reopening it there opened a menu after the focus had gone back to the app, which then would not close on a click elsewhere.) The widget is a child of Explorer's `Shell_TrayWnd`, so its thread shares input with the taskbar, which the right click has just brought to the front: the menu opens in the foreground without taking it. (A menu on another thread with an owner window of its own had to take the foreground from Explorer and was closed at once.) The menu's modal loop keeps dispatching the widget thread's messages, so the button keeps drawing. The focus returns to the app being dictated into only when the menu has closed; a menu that closes at once, or a list that has not arrived, is logged as a warning; the current language is checked. The list (code + label) is sent by the overlay page through `taskbar_set_languages` whenever the shown languages change, so names and the `shownLanguages` filter have one source. Picking one emits `Event::LanguagePicked(code)`, and the app calls `lib::set_language` on a pool thread (save, `settings://changed`, preload models, restart a running take). The pill is not involved. A click makes the taskbar the foreground window (refusing that leaves no foreground window at all), so the focused window is noted while the pointer moves over the button and handed back on release; the app being dictated into keeps the focus.
- The pill: the taskbar button is another way to show the bubble, so while it is on the app shows no circle and no floating pill of its own, and a pinned overlay is hidden. `window::anchored_geometry` centers the overlay window on the button (clamped to the work area) with the pill 8 px above the taskbar; `overlay://anchor` gives the page the button's position for the pill's pop-out origin, and the page forces the small bubble layout, sends only the pill's shape to the window region (the hidden circle's place stays click-through) and disables dragging. Hover is `overlay://widget-hover`; the pill goes again 600 ms after the pointer has left both the button and the pill (`overlay_hide_idle`). If the button cannot be placed, the normal floating overlay is used.

### Model per language

Harder languages (Arabic, Hindi, Thai...) need a bigger Whisper model; easy ones run fine on a small one. `Settings.languageModels` maps a language code to a model id; `Settings::effective_model` returns that entry for `language`, else `model`. "auto" never has its own entry (the language is unknown before decoding), so it uses `model`. `SttService::is_ready` and `with_recognizer` resolve `effective_model`; the loaded recognizer is keyed by the model folder, so changing the language to one with another model frees the old model and loads the new one at the start of the next take (picking a language in the overlay already restarts the take). The **Model per language** card on the Languages page (`LanguageModelsCard`, under the dictation language and the overlay-menu list) lists the languages chosen for the overlay menu (`shownLanguages`, chosen in the card above, plus any language that already has a model), or every language, with a search box, when that menu shows all. Each row has a checkbox and one drop-down listing "Default" (which removes the entry) and every installed model. A search box appears when more than five languages are listed. Ticking several rows (or "Select all") and choosing a model in the bulk drop-down gives them all that model at once. "Same model for all" in the card heading clears every entry. Changes save like every other setting. Model lists in Settings (the Speech model radio list and these pickers) show only the size ("small", "large-v3 turbo"; `shortModel` in `pages/settings/shared.tsx` drops the "Whisper" prefix, which the section already names). The per-language model pickers are always drop-downs (searchable above five models), so a row never wraps. Every `SearchSelect` menu is `position: fixed` at its button (flipped above when there is no room below), so the card's scroll area never clips it. The button itself is as wide as the longest option whichever is picked (each option's label is also rendered invisibly, stacked in the button's grid cell: `.ss-size`; capped at 340 px, longer text is cut with an ellipsis), so the width does not change with the selection. In the Model per language list the rows share one grid column (`.lang-model-list`, rows are subgrids) at the right end of the row: every drop-down there fills it, so they all have the width of the longest option of any row. The menu closes on a scroll only when the button actually moved (a card nudging itself as the menu opens used to close it at once, so the first click after changing page did nothing), and it scrolls its own list to the active option instead of using `scrollIntoView`; focus goes to the menu or its filter box with `preventScroll`, because focusing it scrolled the card around the fixed menu. The menu is as wide as its longest option (`width: max-content`, at least 180 px when it has a filter box, at most 420 px or the room left to the window's edge), not as wide as the button. The settings cards reserve their scrollbar gutter (`scrollbar-gutter: stable`), so a dropdown opening past the last row, which makes the card scroll, does not narrow the content or re-wrap the text above. The catalog also offers Whisper large-v3 turbo (int8, SHA-256 pinned; medium and large-v3 are deliberately not offered); other Whisper folders in the models folder still show as "Existing" and can be chosen per language too.

### Models in memory, auto-load, your own models

`SttService` keeps every model it has loaded (one entry per model folder and provider) until it is unloaded; a take uses the entry for its language's model and loads it first if it is missing. `preload` loads the models chosen for start-up on a thread (`lib::preload_models`, at launch and after a change of device, model, language, per-language models or the auto-load list): `Settings.autoLoadModels`, or, while the user never chose, the default model and the one for the dictation language. Each installed model's row in Settings > Speech model has an **Auto-load** switch (adds or removes it from that list), a **Load** button (shown while it is not loaded) and an **Unload** button (while it is), both behind a confirmation dialog; a "Loaded . GPU/CPU" badge shows what is in memory (`stt_loaded`, polled every 1.5 s). Unloading frees memory only; no file is touched.

**Hiding.** Each row has a hide button (eye-off) that adds the model to `Settings.hiddenModels`; hidden models leave the Speech model list and the Language models pickers (unless one is the default or already chosen for a language, and the default cannot be hidden) and wait in a collapsed "Hidden models (N)" section under the list, where Show brings them back. Nothing is deleted. "Add your own model" sits under the list, above that section.

**GPU.** A model runs on the GPU when the device is GPU and the CUDA pack is active, except models whose files are ONNX Runtime `.ort` files (the Moonshine Arabic build): those are saved already optimised for the CPU, and on the CUDA provider the runtime aborts the whole process, so `ModelFiles::cpu_only` forces the CPU and the badge reads "CPU only" (`gpuBlocked`). Moonshine v1 (`.onnx`) was checked on CUDA and runs.

**Add your own model.** The button picks a folder (a sherpa-onnx download unpacked by the user). `engine::detect` recognises it from its files: Whisper (encoder + decoder), Moonshine v2 (encoder + merged decoder) and v1 (preprocess, encode, cached/uncached decode), a transducer (encoder + decoder + joiner), or a single model file whose folder name says the family (dolphin, omnilingual, sense, paraformer, zipformer-ctc, nemo/conformer/ctc). The path is stored in `Settings.userModels` and listed as "Yours"; nothing is copied or deleted, and there is no remove button. Only Whisper is told a language. The catalog stays the four Whisper models (tiny, base, small, large-v3 turbo); every other model, for example the Arabic-only sherpa-onnx-moonshine-base-ar-quantized (about 120 MB), is something the user downloads and adds.

### Language menu in the small pill

The small pill has a language chip (globe + code) and the same menu opens on a right click anywhere on the pill header (`PillMenu` `openRef`). The menu's rectangle (`dictation_overlay_menu`) and the bubble's (`dictation_overlay_bubble`) are separate window-region rectangles; the bubble is hidden while the menu is open. Picking a language while listening restarts the take in that language, like in the full card.

Small overlay style (`overlayStyle`, Settings > Overlay, shown unless the layout is large only): `pill` (default) is one pill with the mic inside, always shown. `bubble` keeps only a 44 px circle on screen (`.overlay-card.mini.bubble`, centered in the pill's box) holding the state icon and the mic button; the pill, without the mic, shows 6 px above it while dictating, while hovered (after 120 ms; it hides 600 ms after the pointer leaves) and while its language menu is open. A right click on the circle shows the pill. The pill pops out of the circle (`.overlay-pill` fades in while scaling up from the circle's center with a slight overshoot, and shrinks back into it when hidden; no transform at rest). Pill and circle are separate shapes with a 6 px gap; the mic button has a tinted halo. The live text and the review editor float above the pill. The window never moves or resizes for this: the page sends the visible shapes with `dictation_overlay_card` (circle, plus the pill while shown; the pill's shape is added before it shows and dropped once it has gone back into the circle) and the window region is cut to them (`CARD_RECTS` in `window.rs`, small layout only). `MENU_ROOM` is 300 px so the editor fits above the pill.

The small pill always fits its header: every header item keeps its natural width and only the status label shrinks (to 44 px, with an ellipsis). The page measures the header (`pillMinWidth`) on each render and calls `overlay_fit_width` when the window is narrower than that; the command only grows the width (clamped 320-800), saves it, and applies even while `overlaySizeLocked`. The resize handle cannot drag below the measured width.

The language menu hangs from the chip's outer side (left-aligned when the chip is on the window's left half, as in the bubble pill, right-aligned otherwise) and is kept at least 8 px inside the window. It uses concentric corners: menu radius 16 px with 5 px padding, rows 11 px (`MENU_RADIUS` in `window.rs` matches), an even shadow so the region clip cuts every corner the same, a fixed-width code column and the check mark at the row's end.
